 1. OVERVIEW
================================================================================

Synthphony is a single-host homelab platform with four planes:

  • BridgeCade  — Ingress (Caddy), DNS (Pi-hole), VPN (WireGuard), auto-TLS
  • MetronOmni  — Monitoring: Portainer, Uptime Kuma, Netdata
  • OrchestrAI  — AI stack: Ollama, OpenWebUI, Windmill, AgentZero
  • MYestro     — Personal cloud: Nextcloud, Solidtime

All services are accessible via *.synth.home.arpa over HTTPS on your LAN/VPN.
BridgeCade handles all ingress — app stacks never expose ports to the network.

 2. PREREQUISITES
================================================================================

Hardware
────────
  • Linux host (Ubuntu 22.04+, Debian 12+, or similar)
  • Minimum 16 GB RAM (32 GB recommended for AI workloads)
  • SSD recommended for databases and model storage
  • (Optional) NVIDIA GPU for Ollama acceleration

Software (installed automatically by setup scripts)
───────────────────────────────────────────────────
  • Docker Engine + Docker Compose v2
  • (Optional) NVIDIA Container Toolkit (for GPU)

Network
───────
  • Static or DHCP-reserved IP for the host (e.g., 192.168.178.77)
  • Router access to change DHCP DNS settings
  • (Optional) Port forwarding for WireGuard UDP port (default 51820)

 3. AUTOMATED SETUP (ZERO-TOUCH)
================================================================================

Step 1: Copy Synthphony to /opt/Synthphony
──────────────────────────────────────────
  sudo mkdir -p /opt/Synthphony
  sudo cp -r ./BridgeCade ./MetronOmni ./OrchestrAI ./MYestro ./scripts ./backups /opt/Synthphony/
  sudo chown -R $USER:$USER /opt/Synthphony
  cd /opt/Synthphony

Step 2: Run setup-all.sh (one time)
───────────────────────────────────
  ./scripts/setup-all.sh

  This automatically:
    ✓ Installs Docker (if missing)
    ✓ Adds your user to the docker group
    ✓ Creates the bridgecade_web Docker network
    ✓ Detects LAN IP, subnet, and WireGuard defaults
    ✓ Resolves port 53 conflicts (systemd-resolved)
    ✓ Generates all secrets and passwords
    ✓ Creates .env files from .env.example templates
    ✓ Creates all data directories with correct permissions
    ✓ Builds custom Docker images (AgentZero, cert-issuer, dns-registrar)

  ⚠ If prompted about Docker group changes:
    → Log out and log back in, then continue to Step 3.

Step 3: Start everything
────────────────────────
  ./scripts/start-all.sh

  This starts stacks in order:
    1. BridgeCade  (infrastructure first — Caddy, Pi-hole, WireGuard)
    2. MetronOmni  (monitoring)
    3. MYestro     (personal cloud)
    4. OrchestrAI  (AI stack)

  Each stack retries up to 3 times and runs health checks.

Step 4: Verify
──────────────
  docker ps

  You should see containers for all services running.

 9. TROUBLESHOOTING
================================================================================

Problem: Internet disappears after starting BridgeCade
──────────────────────────────────────────────────────
  Cause:  DNS now points to Pi-hole, which may not be ready yet.
  Fix:    Wait 30 seconds for Pi-hole to start, or temporarily:
          echo "nameserver 1.1.1.1" | sudo tee /etc/resolv.conf

Problem: "Not Secure" / certificate warnings in browser
──────────────────────────────────────────────────────
  Cause:  mkcert CA not trusted on your device.
  Fix:    Install rootCA.pem (see Section 7).

Problem: Can't reach *.synth.home.arpa
──────────────────────────────────────
  Check 1: Is Pi-hole running?
           docker ps | grep pihole
  Check 2: Is DNS pointing to Pi-hole?
           dig nextcloud.synth.home.arpa @192.168.178.77
  Check 3: Is Caddy running?
           docker ps | grep caddy
           docker logs bridgecade-caddy
  Check 4: Are cert-issuer and dns-registrar running?
           docker ps | grep bridgecade-cert
           docker ps | grep bridgecade-dns
           docker logs bridgecade-cert-issuer
           docker logs bridgecade-dns-registrar

Problem: Port 53 already in use
───────────────────────────────
  Cause:  systemd-resolved stub listener.
  Fix:    setup.sh handles this automatically (prompts Y to fix).
  Manual: sudo sed -i 's/#DNSStubListener=yes/DNSStubListener=no/' \
            /etc/systemd/resolved.conf
          sudo systemctl restart systemd-resolved

Problem: Docker image pull fails ("not found")
─────────────────────────────────────────────
  Cause:  Stale or incorrect image tag in compose.yaml.
  Fix:    Check Docker Hub for current tags and update compose.yaml.

Problem: Container keeps restarting
──────────────────────────────────
  Check:  docker logs <container-name>
          docker inspect <container-name> | grep -A5 State

Problem: Portainer locked out (took too long on first visit)
───────────────────────────────────────────────────────────
  Fix:    docker compose -f /opt/Synthphony/MetronOmni/compose.yaml down
          rm -rf /opt/Synthphony/MetronOmni/portainer-data
          docker compose -f /opt/Synthphony/MetronOmni/compose.yaml up -d
          → Visit immediately within 5 minutes

Useful diagnostic commands:
  docker ps -a                          # all containers
  docker network ls                     # all networks
  docker network inspect bridgecade_web # ingress network
  sudo ss -tlnp | grep -E ':80|:443|:53' # port usage
  docker system df                      # disk usage

What to back up:
  • /opt/Synthphony/BridgeCade/mkcert-ca/     (CA — critical)
  • /opt/Synthphony/BridgeCade/certs/          (leaf certificates)
  • /opt/Synthphony/BridgeCade/wireguard/      (VPN keys & peer configs)
  • /opt/Synthphony/BridgeCade/pihole/         (Pi-hole state)
  • /opt/Synthphony/MYestro/nextcloud/         (Nextcloud data + DB)
  • /opt/Synthphony/OrchestrAI/windmill/       (Windmill data + DB)
  • /opt/Synthphony/OrchestrAI/ollama/         (AI models — optional, large)
  • All .env and secrets/ files

Simple backup script:
  BACKUP_DIR="/opt/Synthphony/backups/$(date +%F)"
  mkdir -p "$BACKUP_DIR"

  # Database dumps (while running)
  docker exec myestro-nextcloud-db mysqldump -unextcloud \
    -p"$(grep NEXTCLOUD_DB_PASSWORD /opt/Synthphony/MYestro/.env | cut -d= -f2)" \
    nextcloud > "$BACKUP_DIR/nextcloud.sql"

  docker exec orchestrai-windmill-db pg_dump -U windmill -d windmill \
    > "$BACKUP_DIR/windmill.sql"

  # File backups
  tar czf "$BACKUP_DIR/configs.tar.gz" \
    /opt/Synthphony/BridgeCade/mkcert-ca \
    /opt/Synthphony/BridgeCade/certs \
    /opt/Synthphony/BridgeCade/wireguard \
    /opt/Synthphony/BridgeCade/pihole \
    /opt/Synthphony/BridgeCade/secrets \
    /opt/Synthphony/MYestro/secrets \
    /opt/Synthphony/OrchestrAI/secrets \
    /opt/Synthphony/*/.env

Restore:
  1. Stop all stacks: ./scripts/stop-all.sh
  2. Restore files from tar archives
  3. Import SQL dumps into fresh database containers
  4. Start all stacks: ./scripts/start-all.sh

================================================================================
 13. POST-MIGRATION CHECKLIST (When Moving to a New Host)
================================================================================

When migrating Synthphony from one machine (e.g., local PC) to another
(e.g., mini PC server), follow these steps:

Step 1: Clean Up Old Host
─────────────────────────
 Remove old /etc/hosts entries on the OLD machine:
 sudo sed -i '/synth\.home\.arpa/d' /etc/hosts

 Without this, the old host resolves *.synth.home.arpa to its own IP
 instead of the new server, causing "Connection Refused" errors.

 Verify:
 grep synth /etc/hosts
 # Should return nothing

Step 2: Update Router DNS
─────────────────────────
 Point your router's DNS to the NEW server IP.
 For Fritz.box:
 1. Open http://fritz.box
 2. Internet → Zugangsdaten → DNS-Server
 3. Set Lokaler DNS-Server to: <NEW-SERVER-IP>
 4. Click Übernehmen

Step 3: Renew DHCP on All Devices
─────────────────────────────────
 After changing router DNS, devices need to refresh:
 # Linux:
 sudo systemctl restart NetworkManager
 # Or disconnect/reconnect WiFi

Step 4: Verify Firewall on New Host
───────────────────────────────────
 Docker requires IP forwarding and iptables FORWARD policy ACCEPT:
 sudo sysctl net.ipv4.ip_forward
 # Must show: net.ipv4.ip_forward = 1

 sudo iptables -L FORWARD -n | head -1
 # Must show: Chain FORWARD (policy ACCEPT)

 If not, run setup.sh which configures this automatically:
 cd /opt/Synthphony/BridgeCade && ./scripts/setup.sh

Step 5: Install mkcert CA on Your Devices
─────────────────────────────────────────
 Copy the CA certificate from the new server:
 scp <user>@<NEW-SERVER-IP>:/opt/Synthphony/BridgeCade/mkcert-ca/rootCA.pem ~/Downloads/synthphony-ca.pem

 Install per-platform (see Section 7 above).

Step 6: Configure Tailscale DNS (If Using Tailscale)
────────────────────────────────────────────────────
 1. Go to https://login.tailscale.com/admin/dns
 2. Add custom nameserver: <NEW-SERVER-IP>
 3. Restrict to domain: synth.home.arpa
 4. Enable "Override local DNS"

 Without this, phones on 5G cannot resolve *.synth.home.arpa.

Step 7: Verify Everything
─────────────────────────
 From your local PC:
 dig agentzero.synth.home.arpa @<NEW-SERVER-IP> +short
 # Should return: <NEW-SERVER-IP>

 curl -k https://agentzero.synth.home.arpa
 # Should return HTML

 From phone on 5G (with Tailscale connected):
 Open https://agentzero.synth.home.arpa in browser

 From phone on home WiFi:
 Open https://agentzero.synth.home.arpa in browser

 14. FIREWALL SETUP (Pop!_OS / Ubuntu)
================================================================================

Synthphony requires specific firewall rules to:
  • Allow LAN/VPN access to web services (Caddy)
  • Restrict DNS (port 53) to LAN/VPN only (prevent open resolver)
  • Allow WireGuard VPN connections from anywhere
  • Protect SSH and other services

Step 1: Install ufw
───────────────────
  sudo apt install ufw -y

Step 2: Set Defaults
────────────────────
  sudo ufw default deny incoming
  sudo ufw default allow outgoing

Step 3: Allow SSH (adjust if needed)
────────────────────────────────────
  # Option A: SSH from anywhere (default)
  sudo ufw allow ssh

  # Option B: SSH from LAN/VPN only (more secure)
  sudo ufw allow from 192.168.178.0/24 to any port 22
  sudo ufw allow from 10.66.66.0/24 to any port 22

Step 4: Allow Synthphony Services
─────────────────────────────────
  # Caddy HTTP/HTTPS — LAN only
  sudo ufw allow from 192.168.178.0/24 to any port 80 proto tcp
  sudo ufw allow from 192.168.178.0/24 to any port 443 proto tcp

  # Pi-hole DNS — LAN + WireGuard only (CRITICAL: prevents open resolver)
  sudo ufw allow from 192.168.178.0/24 to any port 53
  sudo ufw allow from 10.66.66.0/24 to any port 53

  # WireGuard VPN — must be open to all for remote access
  sudo ufw allow 51820/udp

Step 5: (Optional) Allow VPN Clients Full Access
────────────────────────────────────────────────
  # If you want WireGuard clients to access all services
  sudo ufw allow from 10.66.66.0/24 to any port 80 proto tcp
  sudo ufw allow from 10.66.66.0/24 to any port 443 proto tcp

Step 6: Enable Firewall
───────────────────────
  sudo ufw enable

  Type 'y' when prompted to confirm.

Step 7: Verify
──────────────
  sudo ufw status verbose

  Expected output:
  ─────────────────────────────────────────────────────────────
  Status: active

  To                         Action      From
  --                         ------      ----
  22/tcp                     ALLOW       Anywhere
  80/tcp                     ALLOW       192.168.178.0/24
  443/tcp                    ALLOW       192.168.178.0/24
  53                         ALLOW       192.168.178.0/24
  53                         ALLOW       10.66.66.0/24
  51820/udp                  ALLOW       Anywhere
  80/tcp                     ALLOW       10.66.66.0/24
  443/tcp                    ALLOW       10.66.66.0/24
  ─────────────────────────────────────────────────────────────

⚠️ IMPORTANT: Adjust IP ranges if your LAN or WireGuard subnet differs!

Troubleshooting
───────────────
  # Check status
  sudo ufw status

  # Disable temporarily
  sudo ufw disable

  # Re-enable
  sudo ufw enable

  # Delete a rule (use numbered status)
  sudo ufw status numbered
  sudo ufw delete 3

  # Reset all rules
  sudo ufw reset

⚠️ Docker and ufw
─────────────────
By default, Docker may bypass ufw rules. If you need strict enforcement:

  sudo nano /etc/docker/daemon.json
  # Add: {"iptables": false}
  sudo systemctl restart docker

WARNING: This may break container networking. Only enable if you understand
the implications.
